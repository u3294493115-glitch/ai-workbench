## 总原则

> **AI 主导判断 + 人验证 + 审核范围先定后审。**
>
> AI 负责：明确审核范围、生成核对清单、对每项做"已核验 / 已完成搜索仍未找到 / 已找到但关键字段无法视觉识别 / 明确不满足"五态判断、引用原文位置、给出商务/技术自评。
>
> 人工负责：实物签章 / 装订 / 密封 / 保证金到账 / 证书真伪 / 法规条文最终解释——这些是 **AI 客观无法完成的事项**，必须在 Step 0.5 审核范围声明中先与用户约定。

## 风险优先级（强制遵守）

### 第一优先级：资格审查——零容错（Stage 2）

**目标**：**保证不因任何一项资格条件不满足而废标。**

资格条件必须**逐项、逐字段**核对。**任何以下情形均作为最高级风险处理**：

- 证明材料遗漏（仅当"已完成针对性搜索仍未找到"才允许标 ❌缺失）
- 证书类型错误（注册 vs 职业资格）
- 证书等级不符
- 证书过期
- 项目经理姓名不一致（六处逐字比对）
- 社保姓名、单位、月份等关键字段无法证明
- 承装许可证遗漏
- 安全生产许可证遗漏
- 其他资格硬条件不满足

**资格审查完成前，不得先把商务失分作为报告最高风险。**

### 第二优先级：商务评分（Stage 3）

**目标**：**避免本来可以得分，却因为材料遗漏或理解错误而失分。**

- 商务评分项不得分 **≠** 废标。
- **除非** Step 0.5 范围声明 + Stage 1.5 冻结后的资格审查表 **明确规定** 会导致否决，否则 **禁止** 自行推导："商务不得分 → 虚假响应 → ★条款不通过 → 废标"。
- 如果投标人确实没有对应业绩，则正常判该项 0 分，计算商务总分。
- **异常提醒**：商务总分预计为 0 分，必须单独警示，但 **不得** 自动判废标。

### 第三优先级：技术审核（Stage 4）

- 仅在 Step 0.5 审核范围声明中约定"包含技术"时执行。
- 技术方案写得一般、亮点不足 → 属于评分竞争问题，不直接升级风险。
- 只有明确违反 **实质性技术要求** 时，才升级为高风险。

## v3.3.1 行为约束增量（2026-09-04）

> 适用范围：在已有 v3.3.0-pymupdf 21/21 测试 PASS 之上，收口本次该项目真实运行暴露的 4 类机制缺陷。**不重构既有内容**，仅追加强制行为约束。

### 视觉失败分级（强制）

任何视觉调用必须按以下状态返回并写入 `_work/vision_calls.json`：

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `ok` | 视觉返回结构化结果 | 正常使用 |
| `rejected` | VLM API 内容策略拒绝（视觉 API 1026 / prompt sensitive 等） | ① 立即重试 1 次，使用脱敏 prompt（移除姓名 / 身份证 / 证书编号等具名提示词）；② 重试仍失败 → 标记 `vision_blocked`；③ 状态必须写入 `_work/vision_calls.json` |
| `timeout` | 调用超时 | 重试 1 次；失败 → `vision_blocked` |
| `low_confidence` | 返回但置信度不足（如手写字段、低对比度） | 触发二次复核：放大 2.5x 重渲染 + 独立第二次识别；两次结果不一致 → 标记 `unconfirmed`，不得写入确定性结论 |

**禁止**：把 `rejected` / `timeout` 的页面当作"已视觉核验未发现"。

### 连续证书页聚合（强制）

任何"证书包"——表现为相邻视觉候选页、内容主题连续（如"建造师注册证书 / 执业资格证书 / 社保 / B证"）——必须按**同一个证据包**聚合：

- 单页失败不能否决整组证据；
- 单页成功不能代替整组证据；
- 整组全部视觉被拒或低置信 → 整组 `vision_blocked`；
- 整组部分成功 → 必须列出每页证据内容并交叉核对（如：注册证书 vs 执业资格证书是不同证书类型，必须分别记录）。

### 候选页消费门禁（强制）

对每条拟记 0 分 / "未发现" / "不满足"的结论，Stage 2 必须先调用 `scripts/py/evidence_manifest.mjs` 生成 `_work/evidence_manifest.json`，并满足：

- 该评分项的 `status` 必须是 `complete` 或已记录的 `vision_blocked`；
- `incomplete` 状态**不得**声称"已视觉核验未发现"——必须明确"未视觉核验 / 候选页未消费"。

报告生成阶段必须读取 manifest；任何状态为 `incomplete` 的评分项不得在报告中标 0 分；只能标 "⚠️ 未视觉核验 — 候选页未消费，待人工/下次运行处理"。

### 字段置信度（强制）

任何视觉识别的关键字段（姓名、身份证号、证书编号、日期、金额、有效期）必须记录来源：

- `text_layer`：直接来自 PDF 文字层
- `vision_printed`：视觉识别印刷体
- `vision_handwritten`：视觉识别手写体（默认 `low_confidence`，必须二次复核）
- `manual`：人工输入

涉及高风险矛盾（如日期倒置）时，`vision_handwritten` 必须二次复核后才能作为判断结论；复核仍不一致 → 报告 `unconfirmed`，附"AI 无法判断，请人工核对原件"。

### 候选规则隔离（强化）

报告所有判断结论的依据只能来自：

1. 招标文件原文（事实）
2. 投标文件原文（事实）
3. SKILL.md / references/专业知识规则库.md 已批准的 R 类规则
4. references/常见踩坑经验.md 已批准的 C 类 / P-XXX 案例

**禁止**：
- `references/候选经验区.md` 中任何条目不得作为正式判断依据；
- AI 一般知识 / 推断不得单独作为判断依据；
- 若需要引用候选经验，仅用于"提醒"而非"判定"。

- 上述闸门未通过时报告模块 1 一页摘要必须显式注明"未通过 Stage X → 暂停进入 Stage X+1"

## Stage 2｜资格零容错审核（含反向攻击扫描）

#### 2.1 三态判断（v3.2.0 取代 v3.0.0 五态；针对资格审查）

资格审查状态模型收口到 **三态**：

| 状态 | 含义 | 触发条件 |
|---|---|---|
| **✅ 满足** | 关键字段已 L1 高清视觉识别或文字层确认全部满足招标要求 | 记录已读取关键字段值（带引号原样） + 页码 |
| **❌ 不满足** | 关键字段已识别且与招标要求不符；或资格硬条件已完成针对性搜索仍未找到 | 记录具体字段差异（带引号原样） + 缺失页面区间 |
| **❓ 无法确认** | AI 已有判断所需信息但当前受客观限制无法给出 ✅ / ❌ | **必须三要素**：原因（为什么现在不能判断） / 已核验（已检查什么） / 下一步（还能怎么做） |

**❓ 的两种情形**（v3.2.0 显式拆分）：

- **情形 A：🔎 AI 尚未完成检索**——AI 自己还能做的搜索未完成（文字层 grep + 候选页视觉核验 + 跨页连续检查 + 关键字段识别 + 结构化判断）；必须先完成才能升级为 ❌缺失或给出 ✅
- **情形 B：⚠️ 已找到但关键字段无法视觉识别**——已完成针对性搜索且已渲染高清，但多模态工具仍无法识别关键字段；明确写出"已发现[文件类型]，但[具体字段]视觉识别失败，需人工查看原页 PXX"

两种情形不可混淆——情形 A 是"还没找"，情形 B 是"找了但看不清"。

**禁止措辞清单**（v3.2.0 写死；报告中出现任一 → E-021 FAIL）：

- 初步满足 / 基本满足 / 原则上满足
- 大概率满足 / 应该满足 / 暂定满足
- 倾向满足 / 部分满足但总体通过
- 默认承诺 / 推测满足

**禁止**：
- ❌ 把"明确不一致"写成 ❓"无法确认"——必须给 ❌
- ❌ 把 ❓ 的情形 A "AI 尚未完成检索"写成情形 B"已找到但无法视觉识别"——前者是"还没找"，后者是"找了但看不清"
- ❌ 把"AI 自己还能做的搜索"甩给人工——只有 **实物签章 / 真伪核验 / 保证金到账 / 主管平台登录** 这类客观 AI 无法完成事项才能进入"人工确认"
- ❌ 用文字层结论替代视觉识别——文字层仅用于定位
- ❌ 用 🔵 或其他模糊状态替代三态

#### 2.1.1 🔎 标记前置穷尽搜索清单（v3.0.2 新增；R4 根因收口）

**v3.0.1 漏洞**：🔎 标记的退出条件仅"AI 主观判断"，导致"未搜到 = 不存在"被静默推断；"未规定"被静默补全。

**v3.0.2 收口**——🔎 标记的前置**强制 6 类**穷尽搜索清单（针对每一条 Stage 2 项）：

```
[1] 文字层全文 grep 关键字（含同义词 / 全角半角 / 中英文）
[2] 目录 / 页码索引定位候选页
[3] 候选页 L1 高清渲染（@2.5x；canvas 渲染 PNG）
[4] 跨页连续检查（当前页不完整 → 检查连续后续 3 页）
[5] 视觉核验关键字段（含 L2 高缩放关键区域二次核验）
[6] 结构化判断（如联合体等）→ 必须完成 ≥3 处独立证据点的定向搜索
    - 联合体共同投标协议书（如有）
    - 投标文件主体（封面 / 目录 / 声明函）
    - 投标文件附件（业绩一览表 / 联合体声明）
```

**只有上述 6 类全部完成且均无证据**，才允许判 `❌ 已完成针对性搜索仍未找到`。

**禁止**：
- ❌ 仅文字层 grep 未命中 → 直接判"未搜到" → 推断"不存在"
- ❌ 仅 1~2 类搜索 → 直接判 ❌缺失
- ❌ 联合体 / 主体结构 / 资质主体等**结构化判断**仅凭文字 grep 未命中即下结论
- ❌ 把"本次未找到金额数字"等同为"招标未规定最低业绩金额"——必须回到原文文字层、表格单元格、附件等多处分别核验后才能判定"未规定"

**判定"招标未规定 X" 的最低证据（v3.0.2 新增）**：
- 必须显式列出"为判断 X 已规定，我搜了 [1][2][3][4][5][6]"
- 全部无命中才能判定"未规定"
- 任一未搜就判定"未规定" → 视为 AI 创造条件，等同 ❌

#### 2.2 定向视觉核验流程（v3.0.0 新增）

详见 `references/文件解析与视觉核验策略.md` 第 5.8 节"定向视觉核验流程"。

每个资格硬条件的核验必须遵循：

```
[1] 列出本条件要求的"必须证据集"
   例：注册建造师执业证书 → 证书主体页（带"注册"二字）
[3] 用文字层 /目录定位候选页（仅定位，不下结论）
[4] 对候选页进行 L1 高清渲染（canvas 渲染 PNG @2.5x）
[5] 视觉读取关键字段（多模态工具识别）
[6] 如当前页不完整 → 检查连续后续页（E-006 页面连续性）

#### 2.3 拆证据点判断（v3.0.0 强化 E-005）

清单 A 中**一项内部的多个证据点必须分别判断**——**不得**因为一个子项 ❓ 无法确认（含情形 A 🔎 / 情形 B ⚠️），就把其他已确认的子项（✅）一起判错。

```
示例：A-12 项目经理
- A-12.1 等级（一级建造师）  → ✅ 满足
- A-12.2 专业（机电工程）    → ❓ 无法确认（情形 B：⚠️ 已找到但关键字段无法视觉识别）
- A-12.3 证书性质           → ❓ 无法确认（情形 A：🔎 AI 尚未完成检索，继续定向视觉核验）
- A-12.4 B 证               → ✅ 满足
- A-12.5 社保               → ✅ 已核验满足（月份 + 单位可识别）
- A-12.6 姓名（六处）        → ❌ 明确不满足（"曹力峰" vs "曹利峰"）
```

A-12 整体状态 = **❌ 明确不满足**（因 A-12.6 不满足），但 A-12.1 / A-12.4 / A-12.5 已确认满足的子项应保留 ✅ 状态。

## Stage 3｜商务评分（独立阶段）

- 商务评分项 0 分 **≠** 废标
- 除非 Step 0.5 范围声明 + Stage 1.5 冻结后的资格审查表 **明确规定** 会导致否决，否则 **禁止** 自行推导
- 商务总分预计 0 分 → 必须单独警示，但 **不得** 自动判废标

#### 3.1 商务自评与证明材料的判断原则（v3.0.0 收口）

**核心原则**：投标方的商务自评 **仅作为定位线索**，**不构成得分证据**。

判断流程（强制）：

```
[1] 招标评分条件（从冻结后的清单 B 读取）
       ↓
[2] 招标要求的证明材料（评分细则明确列出）
       ↓
[3] 投标文件实际提供的材料
       ↓
[4] 比对[2]与[3] → 判断是否满足评分条件
       ↓
[5] 得分 = f(满足评分条件的情况)
```

**自评与实际材料不一致** → 仅触发**重点复核**（重点回到 [2]~[4] 流程）。

**禁止**：
- ❌ **禁止**建立"自评与材料矛盾 = 自动 0 分"的机械规则
- ❌ **禁止**仅采信自评（不核对实际材料）
- ❌ **禁止**因自评文字漂亮就给予更高得分
- ❌ **禁止**以"自评是商业行为/营销话术"为由忽略——必须回到证明材料核对

**最终得分**必须由**当前招标文件评分规则 + 实际有效证明材料**共同决定。

#### 3.2 自评矛盾的处理动作

当 AI 检测到商务自评 ↔ 业绩一览表 ↔ 业绩证明材料**三者不一致**时：

1. 在报告中标注"自评与材料不一致，需重点复核"
2. 回到 Stage 3.1 流程 [1]~[4] 重新核对
3. 按实际证明材料情况给出得分（**不**因为矛盾自动判 0）
4. 如证明材料完全缺失 → 按招标评分条件判断该项是否得分（具体条件具体分析）

#### 3.3 商务 0 分项针对性二次证据搜索（v3.2.0 新增）

> **目标**：防止商务 0 分项因 AI 漏读图片 / 漏找材料导致误判。

**触发**：当某商务评分项拟判 0 分时，**必须先完成针对性二次证据搜索**，才能落定 0 分。

**针对性二次证据搜索（按证据类型选择合理方式）**：

| 证据类型 | 推荐搜索方式 |
|---|---|
| **图片型**（银行资信证明 / 信用截图 / 资质证书扫描件 / 业绩证明扫描件 / 体系认证证书） | grep 关键字 0 命中后 → 候选页视觉核验（@2.5x） → 仍未找到 → 判 0 分 |
| **文字层**（合同首页 / 投标函附录 / 业绩一览表 / 资信声明） | grep 关键字（含同义词 / 全角半角 / 中英文） → 仍 0 命中 → 列出文本上下文检索 → 仍未找到 → 判 0 分 |
| **表格型**（业绩汇总表 / 资质清单 / 人员清单） | grep 关键字 + 目录定位 + 候选页表格视觉核验 → 仍未找到 → 判 0 分 |
| **合同型**（合同首页 / 工程范围页 / 签署页 / 验收页） | 4 文件齐全性核验 + 关键字段（合同号 / 容量 / 签约日期 / 竣工日期）逐字比对 → 不齐全或字段不符 → 按招标评分条件判 0 分 |

**禁止**：
- ❌ grep 关键字 0 命中 → 直接判 0 分（未做视觉/上下文/表格核验）
- ❌ 0 分判定时无针对性二次证据搜索记录
- ❌ 图片型材料跳过视觉核验
- ❌ 用"投标人未提供"或"未找到"作为唯一依据判 0 分（必须附搜索记录）

**0 分判定记录格式**（必须写入报告"商务评分"模块对应 0 分项）：

```
【0 分复核记录】
- 证据类型：[图片型 / 文字层 / 表格型 / 合同型]
- 已搜关键词：[关键词 1, 关键词 2, ...]（含同义词 / 全角半角）
- 文字层 grep 命中：[列出实际命中行 / 或 0 命中]
- 候选页范围：[PXX-PXX]
- 视觉核验结果：[每页是否含目标字段 / 或未发现]
- 结论：[仍无证据，判 0 分] / [找到证据，按 XX 给分]
```

[6] 必要时修正或补充当前审核发现
[7] 未命中 → 显式列出已扫描的 ID 集合（不允许"已扫描 / 无命中"含糊措辞）
[8] 写入 _work/report_gate.md（frontmatter 含 run_id / status / completed_at / case_library_path / case_library_sha256 / scanned_ids 或 hit_ids）
```

#### RG.4 产物（必须落盘；v3.3.3 强制 frontmatter）

- `_work/report_gate.md` frontmatter 必含：
  - `run_id`：本次运行唯一 ID（与 `finalize_report.mjs --run-id` 一致）
  - `status`：`hit` / `no_hit` / `read_failed` 三选一
  - `completed_at`：ISO8601 时间戳
  - `case_library_path`：load_case_index 输出的规范化绝对路径
  - `case_library_sha256`：案例库 SHA-256
  - `draft_path`：被扫描草稿的绝对路径（v3.3.3 强制 draft 绑定）
  - `draft_sha256`：被扫描草稿的 SHA-256（v3.3.3 强制 draft 绑定）
- hit 状态必含 `hit_ids`（逗号分隔，必须 ⊆ load_case_index 合法集合）
- no_hit 状态必含 `scanned_ids`（逗号分隔，必须覆盖 load_case_index 合法集合）
- read_failed 状态必含 `failure_reason` + `failure_at`，且 Gate 正文（剥离 HTML 注释后）必须包含"未参考历史案例" + 失败原因 + 失败时间；最终报告 draft 也必须含相同披露块

#### RG.5 与报告模块关系

- 不强制新增"模块 9 历史案例对照"
- 如果命中真实案例，可在 8 模块正文**之后、附录之前**插入简短的"历史案例提醒"小节，仅展示：
  - 命中的案例编号
  - 它提醒检查了什么
  - 最终当前项目直接证据是什么
- 历史案例不得成为最终不符合判断的直接证据

#### RG.6 闸门（v3.3.3 机械闸门）

**唯一允许落盘 `output/审核报告.md` 的程序入口**：`scripts/finalize_report.mjs`

调用流程（强制）：
```
node scripts/finalize_report.mjs \
    --project-root <dir> \
    --run-id <id> \
    --main-audit-completed-at <ISO8601> \
    --draft <path/to/report_draft.md>
```

闸门规则（任意一条不满足 → 拒绝落盘）：
- `_work/report_gate.md` 不存在 → 拒绝（preflight reason）
- `run_id` 与当前 run 不一致 → 拒绝（防复用旧 Gate）
- `Gate mtime < main_audit_completed_at` → 拒绝（防事后补 Gate）
- `Gate completed_at` 早于 `main_audit_completed_at` 或晚于当前 → 拒绝（时间倒序 / 伪造）
- `status == hit` 但 `hit_ids` 包含 load_case_index 未收录的 ID（C-999 之类）→ 拒绝（非法编号）
- `status == no_hit` 但 `scanned_ids` 未覆盖当前正式索引 → 拒绝（防漏扫）
- `case_library_sha256` 与 load_case_index 当前计算不一致 → 拒绝（防篡改）
- `output/审核报告.md` 已存在且未传 `--force-overwrite` → 拒绝（防覆盖）

**禁止**模型绕过 `finalize_report.mjs` 直接 Write / Edit `output/审核报告.md`。
**读取失败**：主体报告**继续落盘**（与 v3.3.2 不同；v3.3.3 统一为"主报告继续 + Gate + 附录显式声明未参考"），但 `_work/report_gate.md` 与报告附录必须显式包含"案例库读取失败 + 失败原因 + 失败时间戳"，禁止"部分参考"等模糊措辞，禁止隐瞒。

## Stage 5｜经验捕获（v3.0.0 重要变更）

> **v3.0.0 关键变更**：AI 不再向历史案例库 / 专业知识规则库写入任何内容。
>
> AI 只能**捕获候选经验**，写入 `references/候选经验区.md`。用户定期回顾候选区，决定是否升级到：
> - C 类（已确认历史案例，需用户授权）
> - R 类（专业知识规则，需用户授权 + 权威依据）

#### 5.1 捕获条件

完成 Stage 4 + 输出报告后，扫描 ❓ 无法确认（含情形 A 🔎 / 情形 B ⚠️） 与 ❌ 不满足 项：

| 触发 | 升级目标 | 写入门槛 |
|---|---|---|
| 真实发生过的事实 + 用户确认 | C 类 | 用户明确授权 |
| 有官方权威依据 + 适用边界明确 | R 类 | 用户明确授权 |
| AI 推测 / 模型一般知识 / 单一项目观察 | 候选经验区 | AI 可自动捕获 |

#### 5.2 候选经验区格式（v3.0.0 新增）

```
[YYYY-MM-DD][AI 推断][未升级]
- 风险描述：（一句话）
- 触发条件：（什么场景会触发）
- 关联项：（关联 A-N.x 或 R-XXX）
- 来源项目：（项目名称 + 日期）
- 待用户判断：升级 C 类 / 升级 R 类 / 不升级 / 已处理
```

#### 5.3 报告里不出现候选编号

**禁止**在最终报告中使用未授权的 P-XXX / C-XXX / R-XXX 编号。AI 发现的候选经验写到候选区，**报告里只描述事实，不引用编号**。

#### 5.4 R 类审批路径（v3.0.0 收口）

**R-Candidate 不属于正式规则，不得用于投标硬判断**。

AI 主动查询官方资料的来源：
- 住建部（住房和城乡建设部）
- 人社部（人力资源和社会保障部）
- 国家法律法规
- 国家标准
- 省级主管部门正式答复
- 其他具有明确权威性的官方来源

晋级正式 R 规则的条件（法规 / 制度型）：
1. 权威依据明确
2. 适用边界明确
3. 用户明确批准

**只有无明确法规依据的经验型规律**，才考虑多项目验证。

## 输出合规检查报告（v3.0.1 决策导向 8 模块 + 落盘 + 首页摘要）

详见 `references/输出格式规范.md`。

**落盘与聊天分工**（v3.0.1 新增）：
- **必须**写入当前项目 `output/审核报告.md`（首屏决策摘要 + 8 模块正文）
- 聊天中**只展示**：首页摘要 + 关键结论（避免用户在长对话里被淹没）
- 报告首页必须让用户**一眼看到**四件事：
  1. **是否建议提交**（建议投标 / 建议补正后投标 / 建议放弃投标）
  2. **必须修改项**（含严重程度标签 🔴 必须修改 / 🟠 重要 / 🟡 建议）
  3. **必须核实项**（人工确认事项 + AI 客观无法完成事项）
  4. **建议修改项 + 严重程度**

**禁止 AI 自行增加审核条件（v3.0.2 新增；R6 根因收口）**：

- 招标原文未规定的金额门槛 / 时间窗口 / 文件类型 / 数量要求 → **不得**作为审核条件
- 例如（**非穷举**）：
  - 招标未规定"最低业绩金额" → 不得把"业绩合同金额 < 某具体数字"作为资格否决
  - 招标未规定"项目经理必须有手写签名日期" → 不得把"缺签名日期"作为资格否决
  - 招标未规定"招标控制价 = 业绩合同金额上限" → 不得把"业绩合同金额与招标控制价不一致"作为资格否决
  - 招标未规定"信用截图必须加盖公章" → 若本轮范围已排除签章检查 → 不得在必核项里再次要求
- 判定"招标未规定 X" 必须满足 R4 6 类穷尽搜索均无命中（见 2.1.1）

报告包含：

1. **一页结论摘要**（限制为"一屏"——明确废标风险 / 必须修改项 / 商务预计得分 / 技术主要失分点 / 总体结论）
2. **资格性符合性审查**（严格按招标文件原始 N 项顺序；这是报告最重要部分）
3. **商务评分项自检**（含评分点对齐）
4. **技术评分项自检**（含评分点对齐；仅 Step 0.5 范围包含时）
5. **报价及重大一致性检查**
6. **模板污染 / 名称 / 姓名 / 日期交叉检查**
7. **签章 / 装订 / 密封 / 保证金到账**（**仅当 Step 0.5 范围包含时**——否则**不展示**）
8. **人工确认事项**（**仅 AI 客观无法完成事项**：实物签章 / 装订 / 密封 / 保证金到账 / 证书真伪 / 法规条文最终解释）

**报告验收标准**：
- [ ] 报告**已写入** `output/审核报告.md`（与聊天展示不冲突，但落盘是主交付物）
- [ ] 报告首页含"AI 报告声明" + "建议提交 / 必须修改 / 必须核实 / 建议修改"四件事
- [ ] 报告包含 8 模块（按 v3 决策导向顺序）
- [ ] 第 1 模块"一页结论摘要"限制为一屏
- [ ] 第 2 模块按招标文件原始 N 项顺序
- [ ] 第 7 模块仅当 Step 0.5 范围包含时展示
- [ ] 第 8 模块仅 AI 客观无法完成事项
- [ ] 报告里**不出现**未授权的 P-XXX / C-XXX / R-XXX 编号
- [ ] 所有表格不溢出 / 不错位
- [ ] 没有"TODO"/"TBD"/"待补充"等未完成标记
- [ ] **不出现**模块 7 "签章 / 装订 / 密封 / 保证金到账"——除非 Step 0.5 用户明确勾选（**默认不出现**）
- [ ] **不出现**"缺签名日期""未盖骑缝章""正副本盖章"等任何**未在招标原文中明确规定**的资格否决项

**测试结果三态证据等级规则（v3.0.2 新增；R5 根因收口）**：

任何验收项 / 任何评估结果只能给出三种状态之一：

| 状态 | 含义 | 适用情形 |
|---|---|---|
| **PASS** | 有真实行为级证据 + 无自相矛盾 | 同一次行为运行的产物（落盘文件 / 实际命令输出） + 实际行为结果一致 |
| **FAIL** | 有真实行为级证据 + 与预期不符 | 同上 |
| **NOT PROVEN** | 无真实行为级证据 / 部分行为级证据 / 仅有静态规则存在 | 仅有"Skill 文本含该条款" / 仅有反例注入测试 / 仅有第三方经验 |

**禁止**：
- ❌ 静态规则存在 ≠ 行为验证 → 不得用"Skill 文本已含 X 条"代替真实运行 → 标 PASS
- ❌ 自相矛盾证据 → 不得标 PASS（必须标 FAIL 或 NOT PROVEN）
- ❌ "未观察到失败" ≠ "验证通过"
- ❌ 真实行为回归测试**未运行** → 明确标 NOT RUN，不得写 PASS

**本规则的来源**：v3.0.1 上一轮"10/10 PASS"报告中，因范围闸门失效（必核/建议/人工确认仍出现签章）+ 静态规则被等同于行为验证，导致真实失败被漏报。v3.0.2 起强制三态证据等级。

### ❌ 禁止

- ❌ 不能做出无依据的乐观判断
