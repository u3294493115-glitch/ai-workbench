## 模块 1｜AI 报告声明 + 一页结论摘要

#### 1.1 AI 报告声明（置顶）

> ⚠️ **AI 报告声明**
>
> 本报告由 AI 基于招标文件与投标文件**文本比对 + 定向视觉核验**自动生成，**不替代人工终检**。
>
> **本报告本次审核范围**（Step 0.5 用户声明）：
> - 投标文件**内容**核验：✅
> - 实物**签章**（公章 / 法人章 / 骑缝章）：[✅ 已检查 / ⚠️ 仅提示未全查 / ❌ 未检查]
> - 实物**装订 / 密封**：[同上]
> - **投标保证金到账**：[同上]
> - **证书真伪**（官方平台核验）：[同上]
> - **Stage 4 技术审核**：[✅ 已执行 / ❌ 未执行]
>
> AI 客观无法完成事项（不在本报告覆盖范围）参见第 8 模块"人工确认事项"。
>
> **范围声明全报告零出现承诺（v3.0.2 新增）**：
> 本报告 Step 0.5 排除项在报告**全报告位置**（模块 1 / 模块 2 / 必核清单 / 建议清单 / 人工确认 / 模块 7）**不得以任何形式出现**。
> 唯一例外：电子证书例外（招标原文 A-12 注释触发时）。
> 自检报告：`output/_work/scope_self_check.md`

#### 1.2 首页四件事（v3.0.1 新增强制）

报告首页必须让用户**一眼看到**：

1. **是否建议提交**（建议投标 / 建议补正后投标 / 建议放弃投标）
2. **必须修改项**（含严重程度标签 🔴 必须修改 / 🟠 重要 / 🟡 建议）
3. **必须核实项**（人工确认事项 + AI 客观无法完成事项）
4. **建议修改项 + 严重程度**（同上标签体系）

#### 1.3 一页结论摘要（限制为"一屏"）

**只保留**：
1. **明确废标风险**（致命风险 / 废标项缺失）
2. **必须修改项**（不修改会导致废标或重大失分）
3. **商务预计得分**（B-01 + B-02 + ... 总分 / 满分）
4. **技术主要失分点**（如有）
5. **总体结论**（建议投标 / 建议补正后投标 / 建议放弃投标）

**不机械限制字数**，但**只允许一屏**——超出部分移到对应模块。

```
【一页结论摘要】

🔴 废标风险：[有 N 项 / 无]
- [项 1]：[一句话]
- [项 2]：[一句话]

🔧 必须修改项：[有 N 项]
1. [修改项 1]：[一句话 + 责任人 + 截止时间]
2. [修改项 2]：[一句话 + 责任人 + 截止时间]

📊 商务预计得分：[X / 20]
- 强响应：[哪些项]
- 0 分项：[哪些项 + 原因]

📊 技术预计得分（仅当执行技术审核）：[X / 40]

✅ 总体结论：[建议投标 / 建议补正后投标 / 建议放弃投标]
```

## 模块 2｜资格性符合性审查（最重要）

**v3.0.0 铁律**：严格按招标文件原始 N 项顺序展示，不**不得**重组或重构。

**v3.0.2 新增**：模块 2 必须显式记录"frozen 路径 + 落地时间戳"，并保证清单 A 项数 = frozen 中 A 项数；任一项不一致 → 报告不得落盘。

```
【frozen 引用】
- 路径：output/_work/frozen_checklist.md
- 落地时间戳：[YYYY-MM-DD HH:MM:SS]
- 清单 A 项数：N 项（与本表 A-01 ~ A-N 严格相等）
```

> **v3.2.0 主表硬约束**：
> 1. 每条招标原文必须出现且原文字符串相等（不得简称化 / 纠错 / 补全 / 推测）
> 2. 一条招标原文可拆成多个核验点（一对多），但所有核验点必须在同一原编号下
> 3. 核验条件必须直接从当前招标原文生成；frozen 仅辅助交叉检查，不作为语义真值
> 4. 投标实际内容必须基于当前投标文件真实证据 + 页码；禁止引用旧报告二手结论；禁止用不对应材料替代
> 5. 三态仅 ✅ / ❌ / ❓；❓ 必须带"原因 / 已核验 / 下一步"三要素
> 6. 不得凭空增加招标要求（不得创造原文中不存在的核验条件）

#### 2.1 表格格式（v3.2.0）

```
| 招标原编号 | 招标原文（一字不差） | 核验条件（来自当前招标原文） | 投标实际内容 | 页码 | 三态判定 | 原因 / ❓ 三要素 |
```

#### 2.2 拆证据点规则（v3.0.0，v3.2.0 强化）

清单 A 的某项（如 A-12 项目经理）内部允许拆核验点：

```
| A-12 | 项目经理二级及以上机电工程注册建造师 + 6 个月社保证明（电子证书例外） | (二级 OR 一级) AND 机电工程 AND 注册 + 6 个月社保；例外：电子证书可官方核验 | P17-P20 投标文件 / P21 B 证 / P22 证书 | P17, P21, P22 | ❌ | A-12.6 姓名字形不一致 |
| A-12.1 | 等级（≥ 二级） | ≥ 二级 | P22 一级建造师职业资格证书 | P22 | ✅ | 等级 ≥ 二级 ✓ |
| A-12.2 | 专业（机电工程） | 机电工程 | P22 仅封面，未识别专业 | P22 | ❓ | 原因：P22 封面未显示专业；已核验：grep "机电工程" P22=命中；下一步：视觉核验 P22 证书主体页 |
| A-12.3 | 证书性质（注册 vs 职业资格） | 注册建造师执业证书 | P22 证书名"职业资格证书" | P22 | ❌ | 招标要求注册；投标仅"职业资格证书" |
| A-12.4 | B 证 | 持有 | 浙建安B(2025)3400532 | P21 | ✅ | B 证编号已核验 |
| A-12.5 | 社保月份 + 单位 | 6 个月内任意 1 个月 + 投标单位注册 | 2026-01~2026-03 | P22 | ✅ | 社保月份 + 单位可识别 |
| A-12.6 | 项目经理姓名（六处逐字比对） | 六处一致 | "曹利峰" vs "曹力峰" | P21, P24, P42 | ❌ | 姓名字形不一致 |
```

**注意**：A-12 是第 12 项原文资格，拆出来的 A-12.1~A-12.6 是 A-12 **内部**核验点，不改变原文 N 项总数。v3.2.0 进一步明确：所有核验点必须挂在同一原编号下。

#### 2.3 状态规则（v3.2.0 三态）

| 状态 | 含义 | 后续动作 |
|---|---|---|
| **✅ 满足** | 关键字段已 L1 高清视觉识别或文字层确认全部满足 | 标记通过，列出已读取关键字段值（带引号原样）+ 页码 |
| **❌ 不满足** | 关键字段已识别且与招标要求不符；或资格硬条件已完成针对性搜索仍未找到 | 记录具体字段差异（带引号原样）+ 缺失页面区间 |
| **❓ 无法确认** | AI 已有判断所需信息但当前受客观限制无法给出 ✅ / ❌ | 必须三要素：原因（为什么现在不能判断） / 已核验（已检查什么） / 下一步（还能怎么做） |

**❓ 的两种情形**（与 SKILL.md Stage 2.1 一致）：

- 情形 A：🔎 AI 尚未完成检索——AI 自己还能做的搜索未完成
- 情形 B：⚠️ 已找到但关键字段无法视觉识别——已完成针对性搜索且已渲染高清，但多模态工具仍无法识别关键字段

#### 2.4 验收标准

- [ ] 每条招标原文必须出现（v3.2.0；不得漏 1 条）
- [ ] "招标原文"列内容 = 招标原文字符串相等（v3.2.0；不得简称化 / 纠错 / 补全 / 推测）
- [ ] 一条招标原文可拆多个核验点（A-N.x），但所有核验点必须挂同一原编号
- [ ] "核验条件"列来自当前招标原文（v3.2.0；不得以 frozen 逻辑表达式作为语义真值）
- [ ] "投标实际内容"基于当前投标文件真实证据 + 页码（v3.2.0；不得引用旧报告二手结论；不得用不对应材料替代）
- [ ] 三态仅 ✅ / ❌ / ❓；❓ 必须带三要素
- [ ] 不凭空增加招标要求（不得创造原文中不存在的核验条件）
- [ ] 不得出现 🔵 或"初步满足 / 基本满足 / 原则上满足 / 大概率满足 / 应该满足 / 暂定满足 / 倾向满足 / 部分满足但总体通过 / 默认承诺 / 推测满足"任一措辞

#### v3.0.0 收口：自评矛盾处理（不机械规则）

**原则**：投标方自评**仅作为定位线索**，**不构成得分证据**。

商务评审索引表自评 ↔ 业绩一览表实际内容 ↔ 业绩证明材料**三者不一致**：

1. 标注"自评与材料不一致，需重点复核"
2. 回到评分条件（清单 B）→ 招标要求的证明材料 → 实际提供的材料 → 判断是否满足
3. **按实际证明材料情况给出得分**（不**因为矛盾自动判 0）
4. 如证明材料完全缺失 → 按招标评分条件判断该项是否得分

**禁止**：
- ❌ **禁止**仅采信自评
- ❌ **禁止**因矛盾直接判 0 分（除非评分条件明确要求"提供 X 材料否则不得分"且实际未提供）
- ❌ **禁止**以"自评是商业行为"为由忽略

详见 `SKILL.md` Stage 3.1 / Stage 3.2。

| 6 | 纸质版与电子版一致性 | AI 未实际比对实物（始终允许） |

**禁止**将以下事项列入"人工确认事项"：
- ❌ AI 自己能做的搜索（🔎 AI 尚未完成检索）→ AI 立即继续执行定向视觉核验
- ❌ AI 已识别的字段差异（如姓名"曹力峰" vs "曹利峰"）→ 在模块 2 明确呈现，不需要人工"再查一次"
- ❌ AI 已知已识识的证书类型问题（如 P22 证书名不含"注册"）→ 模块 2 已识别
- ❌ 投标文件某页是否真的盖章（除非 Step 0.5 范围明确要求）
- ❌ **(v3.0.2 新增)** Step 0.5 排除项——例如范围 = "签章不查" → 不得在模块 8 出现"信用截图是否加盖公章""履约担保到账"等任何变相要求
