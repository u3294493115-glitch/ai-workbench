# 审核范围声明模板（v3.0.0 新增，v3.0.1 微调）

> 本模板用于 **Step 0.5 闸门**——开始审核前必须由用户确认本次范围。
>
> **目的**：解决 v2.1.2"既不完整检查，又零散标红"的系统性问题。

---

## 一、为什么需要审核范围声明

v2.1.2 报告暴露的核心问题：
- 用户未要求检查签章 → 报告**零散提示**"未盖章 / 致命风险"
- 用户未要求检查装订 → 报告**零散提示**"未装订"
- 用户未要求检查技术 → 报告**仍做**技术评分
- 用户未要求检查保证金到账 → 报告**提示**"未到账"

v3.0.0 边界规则：
- 一旦确定某项**不检查**，**整个报告**不得再触发该项风险
- 一旦确定某项**全查**，必须**系统性逐项**检查，不允许"只随机提示几个页面"

## 二、审核范围声明表（用户填写）

### 必填项

| 检查项 | 用户勾选 | 默认（未指定时） |
|---|---|---|
| 投标文件**内容**核验 | □ 是 □ 否 | ✅ 默认**是** |
| Stage 4 **技术审核** | □ 是 □ 否 | ✅ 默认**是** |
| **输出报告** | □ 是 □ 否 | ✅ 默认**是** |

### 实物类（默认仅提示，未全查）

| 检查项 | 用户勾选 | 默认（未指定时） |
|---|---|---|
| 实物**签章**（公章 / 法人章 / 骑缝章） | □ 全查 □ 不查 | ⚠️ 默认**仅提示**（报告中不出现零散标红） |
| 实物**装订 / 密封** | □ 全查 □ 不查 | ⚠️ 默认**仅提示** |
| **投标保证金到账** | □ 全查 □ 不查 | ⚠️ 默认**仅提示** |
| **证书真伪**（住建部 / 人社部平台核验） | □ 全查 □ 不查 | ⚠️ 默认**仅提示**（AI 无法登录官方平台） |
| **法规条文最终解释**（如特定地方性条款理解） | □ 需要 □ 不需要 | ⚠️ 默认**仅提示** |

## 四、声明固化与不可变性

- 本次审核范围声明**固化后不可变更**——除非用户明确表示修改
- AI 报告开头的"AI 报告声明"必须**逐项复述**本次声明（让用户确认范围生效）
- 如果 AI 在审核中**需要越界**（例如本来不查签章，但发现 P25 截图明显未盖章）→ AI 只能**追加提示**，**不得**改判定为"未盖章 = 致命风险"

---

## 五、范围对报告的影响

| 范围声明 | 对应报告模块 |
|---|---|
| 投标文件内容核验 = ✅ | 模块 2 资格性符合性审查 / 模块 3 商务 / 模块 5 报价一致性 / 模块 6 模板姓名日期 — 全部展示 |
| Stage 4 技术审核 = ✅ | 模块 4 技术评分项自检 — 展示 |
| Stage 4 技术审核 = ❌ | 模块 4 — **不展示** |
| 实物签章 = 全查 | 模块 7 签章 — 完整展示 |
| 实物签章 = 仅提示 / 不查 | 模块 7 — **不展示**（个别追加提示可在模块 1 一页摘要注明） |
| 投标保证金到账 = 全查 | 模块 7 保证金 — 完整展示 |
| 投标保证金到账 = 仅提示 / 不查 | 模块 7 — **不展示** |

### 5.1 范围声明全报告硬约束（v3.0.2 新增）

**v3.0.2 收口**：Step 0.5 排除项在报告所有位置（模块 1 一页摘要 / 模块 2 资格 / 模块 3 商务 / 必核清单 / 建议清单 / 人工确认 / 模块 7）必须**全报告零出现**。

| 范围声明结果 | 全报告必须遵守 |
|---|---|
| 签章 = ❌ 不查 | 不得出现"公章未盖 / 法人章 / 骑缝章 / 装订 / 密封 / 盖章占位 / 信用截图盖章"等任何形式 |
| 装订 / 密封 = ❌ 不查 | 不得出现"未装订 / 未密封 / 唱标信封" |
| 投标保证金 = ❌ 不查 | 不得出现"投标保证金未到账 / 履约担保 / 银行回单" |
| 证书真伪 = ❌ 不查 | 不得出现"证书需平台核验 / 真伪待验"（除非触发电子证书例外） |
| Stage 4 技术 = ❌ 不查 | 不得做技术评分；模块 4 整体不展示 |

**唯一允许的例外**：
- 电子证书例外条款（招标原文 A-12 注释）触发时，"全国建筑市场监管公共服务平台核验"可作为"AI 客观无法完成事项"列入人工确认——**仅适用于电子证书**已识别且触发三项条件之一
- 不得把"电子证书例外"机械扩展到实体证书 / 其他业务章 / 其他核验路径

### 5.2 自检报告 `output/_work/scope_self_check.md`（v3.0.2 新增）

**必填字段**：

```
# 范围声明自检报告（v3.0.2 强制）

## 范围声明输入（Step 0.5）
- 投标文件内容核验：
- Stage 4 技术审核：
- 实物签章：
- 装订 / 密封：
- 投标保证金到账：
- 证书真伪：
- 法规条文最终解释：

## 自检动作
1. 列出本次报告所有文件清单：
   - output/审核报告.md
   - 其他衍生 .md（如有）
2. 对每个排除项，grep 全报告文件，记录命中行号：
   - 排除项：签章 → grep "公章 / 法人章 / 骑缝章 / 盖章 / 装订 / 密封" → 命中：[行号 / 文件]
   - 排除项：保证金 → grep "保证金 / 履约 / 银行回单" → 命中：[行号 / 文件]
   - 排除项：证书真伪 → grep "平台核验 / 真伪" → 命中：[行号 / 文件]
   - ...

## 自检结论
- 命中行号 > 0 → 报告必须返工
- 命中行号 = 0 → 通过

## 不通过 → 返工动作
- [返工清单]
```

**位置**：`output/_work/scope_self_check.md`

**生效时机**：报告 `output/审核报告.md` 落盘前必须先生成；若自检结论为"不通过"，报告必须返工。

## 七、input/ 历史残留处理（v3.0.2 新增）

**v3.0.2 明确**：

| 文件状态 | 处理方式 |
|---|---|
| input/_extracted.docx / input/_*.docx（历史运行残留） | 视为"历史污染"；**不得**在本轮报告里记成"本轮新增" |
| 本轮运行开始时 | 必须在 `output/审核报告.md` 附录写"input/ 残留清单"（仅记录 + 建议清理） |
| 本轮运行**新增**任何 input/ 文件 | **禁止** |
| 删除原始招标文件 / 投标文件 | **禁止**（即便有残留文件） |

**与"既不完整检查签章"区别**：v3.0.2 不要求删除 input/ 残留文件；只要求不擅自写入、不擅自删除、不擅自记成"本轮新增"。
