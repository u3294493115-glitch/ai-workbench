# 案例库调用规范

> 版本：v3.3.3（2026-09-04）
> **v3.0.0 重大变更**（相对 v2.1.2）：
> 1. **硬写入闸门**：C / P- 类案例默认只读，AI 不得自动写入或修改
> 2. **不硬编码绝对路径**：外部真实历史案例库位置由用户告知
> 3. **专业知识独立**：R 类（专业知识规则库）独立于 C / P- 类
> 4. **候选经验隔离**：候选经验区不构成判断依据
> 5. **报告里不出现未授权编号**
>
> **v3.3.3 重大变更**（相对 v3.3.2）：
> 1. **统一读取失败处置**：失败 → 主报告继续落盘 + Gate + 附录显式声明"未参考历史案例"（v3.3.2 之前三处规则互斥）
> 2. **路径发现程序化**：`scripts/load_case_index.mjs`（CLAUDE.md 第 8 节 → 案例库绝对路径 + 合法 ID 集合 + SHA-256）
> 3. **机械闸门**：`scripts/check_report_gate.mjs`（preflight）+ `scripts/finalize_report.mjs`（唯一报告落盘入口）
> 4. **动态 ID 集合**：禁止硬编码"6 / 7 / 9 个信号族"，从 load_case_index 当前输出解析

## 一、案例库的法定角色

**案例库是提醒器，不是规则源。**

| 角色 | 是否允许 |
|---|---|
| 提醒"此处可能漏读，回去原文再检查一遍" | ✅ 允许 |
| 提示"此处应参考专业知识规则库 R-XXX" | ✅ 允许 |
| 提供"AI 检查动作"参考模板 | ✅ 允许 |
| **新增招标条件** | ❌ 禁止 |
| **扩大招标要求范围**（如把"6 个月内任意一个月社保"扩大为"必须连续 6 个月"） | ❌ 禁止 |
| **提高招标门槛**（如把"二级建造师"提高为"必须一级"） | ❌ 禁止 |
| **直接生成资格结论**（如"看到分公司就判不合格"） | ❌ 禁止 |
| **AI 自动向历史案例库写入或修改任何 C-XXX / P-XXX 条目** | ❌ 禁止 |

> **铁律**：案例库出现与招标文件原文冲突时，**以招标文件原文为准**。

## 二、知识分层架构（v3.0.0）

```
┌────────────────────────────────────────────────────────┐
│ 第 1 层：当前项目规则（A 类）                            │
│ 来源：当前招标文件原文                                   │
│ 写入门槛：招标文件出现即生效                              │
│ 覆盖权：最高                                             │
└────────────────────────────────────────────────────────┘
            ↑ 不能覆盖
┌────────────────────────────────────────────────────────┐
│ 第 2 层：专业知识规则库（R 类）                          │
│ 来源：官方法规 / 主管部门文件 / 国家级标准                 │
│ 写入门槛：权威依据明确 + 适用边界明确 + 用户明确批准      │
│ 默认：只读                                                │
└────────────────────────────────────────────────────────┘
            ↑ 不能覆盖
┌────────────────────────────────────────────────────────┐
│ 第 3 层：已确认历史案例库（C 类 / P-XXX）               │
│ 来源：真实发生过的错误 / 失败 / 废标 / 扣分案例          │
│ 写入门槛：真实发生 + 事实结果已确认 + 用户明确批准        │
│ 默认：只读                                                │
└────────────────────────────────────────────────────────┘
            ↑ 不能覆盖
┌────────────────────────────────────────────────────────┐
│ 第 4 层：候选经验区（草稿，非正式知识）                  │
│ 来源：AI 在审核中观察到但未经验证的经验                   │
│ 写入门槛：AI 可自动捕获                                  │
│ ⚠ 禁止调用：正常投标审核不得以候选区作为判断依据          │
└────────────────────────────────────────────────────────┘
```

**冲突解决优先级**：A > R > C / P- > 候选经验（不可调用）

低层级不得覆盖高层级。模型一般知识 / 推断属于最底层，不得单独作为判断依据。

## 三、外部真实历史案例库的调用协议

#### 3.1 案例库位置约定

- 外部真实历史案例库的位置由**用户告知**（不硬编码绝对路径）
- Skill 通过调用协议而非物理引用访问
- **Skill 包内不复制**外部案例库内容

#### 3.2 调用动作（v3.3.2 收口）

| 阶段 | 调用动作 | 输出 |
|---|---|---|
| **Stage 1.0 前置** | 仅读 Skill 自带 references（不再读外部案例库） | 通用判断原则 |
| **Stage 1.5 反向查漏** | 仅基于 Skill 自带 references 触发信号扫描招标原文（不读外部案例库） | 反向查漏提示（不直接补充审查表项） |
| **Stage 2.6 反向攻击扫描** | 仅 AI 模拟评委视角反向攻击（不读外部案例库） | 对抗视角报告 |
| **[Report Gate]｜历史案例反向查漏** | **唯一外部案例库调用点**——主体审核完成后、报告生成前，读取触发信号表 + 历史案例清单扫描当前审核发现 | `_work/report_gate.md`（命中案例 / 无命中声明 / 读取失败声明） |
| **Stage 5 经验捕获** | **禁止** AI 自动向外部历史案例库写入；仅在 `references/候选经验区.md` 写入候选经验 | 候选经验（AI 自动捕获） |

#### 3.3 触发信号表（保留 v2.1.2 内容）

| 案例编号类型 | 触发信号 |
|---|---|
| C-001 单位名称 | 保证金、分公司、申请书、回单、单位名称、付款主体 |
| C-002 资格人员 | 资质、业绩、人员、证书、社保、项目经理、承诺函 |
| C-003 税率 | 税率、含税、不含税、报价、总价、付款、发票 |
| C-004 签章 | 盖章、签字、电子签章、正副本、承诺函、偏离表 |
| C-005 保证金 | 厂家、第三方、保证金、代缴、账号、回执、平台识别 |
| C-006 配合厂家 | 配合厂家、联合体、附件完整性、信用截图、标书目录响应 |
| C-007 模板占位符 | 模板、占位符、（投标人名称）、空白字段、签名、日期、社保 |

#### 3.4 正式案例库寻址与调用协议（v0.4 强化，强制）

**正式入口**：`AI审查/历史废标与扣分案例库.md`（无版本号稳定路径，由项目级 `CLAUDE.md` 第 8 节约定）

**v3.x 调用协议**：

1. **路径约定**
   - 本 Skill 不硬编码绝对路径；正式入口路径由项目级 `CLAUDE.md` 第 8 节告知
   - 一律使用 CLAUDE.md 中描述的稳定入口路径，**不得使用 `_v0.3` / `_v0.4` / `_archive/` 等带版本号的归档路径进行正常调用**

2. **Skill 启动时的动作（v3.3.2 收口）**
   - Step 0（文件解析）之前，**不再要求**读取项目级 `CLAUDE.md` 第 8 节作为前置动作
   - 项目级 `CLAUDE.md` 第 8 节路径约定保持稳定（由系统 reminder 加载到上下文即可）
   - 外部历史案例库的读取统一在 **[Report Gate]** 阶段执行（参见 §3.2 与 SKILL.md `[Report Gate]｜历史案例反向查漏`）

3. **审核过程中按需检索（v3.3.3 收口）**
   - **[Report Gate]** 阶段（主体审核完成后、报告生成前）读取外部案例库"触发信号表 + 历史案例清单"（不读全文）
   - **v3.3.3 收口**：扫描输入集**不再**仅限"❌ / ❓ 项"，覆盖以下全部输入（参见 SKILL.md RG.3）：
     - frozen_checklist.md 全部清单项，不限状态
     - Stage 2 / Stage 3 / Stage 4 全部输出（含 ✅ / ❌ / ❓ / ⚠️ / 🔎）
     - evidence_manifest.json 全部评分项
     - 当前报告 draft 的全部判断
     - 当前招标 / 投标解析文本中的触发信号命中位置
   - 对命中的触发信号，**按需**读取该案例的详细章节（标签 / 事件描述 / AI 检查动作 / 推荐输出口径）
   - 历史案例只能作为提醒，**必须**回到当前招标文件 / 投标文件核实直接证据
   - Stage 1 / Stage 2 / Stage 3 / Stage 4 **不再读取**外部案例库

4. **读取失败的处置（v3.3.3 统一）**
   - 案例库文件不存在 / 路径错误 / 读取异常 → `load_case_index.mjs` 返回 `ok=false read_failed=true`
   - **统一策略（v3.3.3）**：主体审核报告**继续落盘**，但 `_work/report_gate.md` 必须含 `status: read_failed` + `failure_reason` + `failure_at`；报告附录必须显式声明"案例库读取失败 + 失败原因 + 失败时间戳"
   - **禁止**假装已参考；**禁止**编造"参考了案例库"的声明
   - **禁止**使用"部分参考"等模糊措辞
   - **禁止**要求用户每次输入"请读取 v0.x 案例库"或"请读案例库"
   - **禁止**因案例库读取失败而否定主体审核已得出的结论

5. **写入治理（保持 v3.0.0 不变）**
   - AI 仍不得自动向外部真实案例库写入或修改任何 C / P-XXX 条目
   - 新增案例必须由 AI 在 `references/候选经验区.md` 写入候选经验，等用户授权后由人工更新到正式入口

6. **版本升级（写入方负责）**
   - 升级时只覆盖无版本号的正式入口文件
   - 旧版本必须保留到 `_archive/` 目录
   - 升级不改外部调用方路径，CLAUDE.md 第 8 节内容不变

## 四、硬写入闸门（v3.0.0 新增，强制规则）

#### 4.1 历史案例库默认只读

**AI 只能输出**："建议新增历史案例：XXX"

必须**同时满足**：
1. 真实发生过（不是模型推测或一般知识）
2. 事实结果已经确认（不是"可能存在风险"）
3. 用户**明确回复同意写入**（不是 AI 默认升级）

**只有得到用户明确授权后**，才能新增或修改历史案例库。

#### 4.2 禁止行为

- ❌ **禁止**在最终报告中使用未授权的 C-XXX / P-XXX 编号
- ❌ **禁止**把"可能存在风险"写成新案例
- ❌ **禁止**AI 自行升级候选经验为正式案例
- ❌ **禁止**AI 自动修改现有 C-XXX / P-XXX 案例内容
- ❌ **禁止**基于"过去发生过"就自动生成"未来必须"的规则

#### 4.3 报告里的编号规则

**报告里只能出现**：
- A 类编号（清单 A 资格项）—— 来自当前项目招标文件
- B / C / D / E 类编号（清单 B/C/D/E）—— 来自当前项目招标文件
- 五态判断标识 ✅ / 🔵 / 🔎 / ⚠️ / ❌

**报告里不得出现**：
- 未授权的 P-XXX 通用规则编号
- 未授权的 R-XXX 专业规则编号
- 未授权的 C-XXX 历史案例编号
- 候选经验区任何编号

AI 发现的候选经验 → 写入 `references/候选经验区.md` → **不引用**到报告里。

## 五、专业知识规则库（R 类）调用协议

#### 5.1 R 类规则定义

**可跨项目复用** + **有官方权威依据**（住建部 / 人社部 / 发改委文件 / 国家级标准 / 主管部门答复）的专业判断。

写入门槛（三选三）：
1. **权威依据明确**：能引用具体文件 / 标准号 / 主管部门答复
2. **适用边界明确**：能说清"适用于 X，不适用于 Y"
3. **用户明确批准**：AI 输出建议 → 用户回复"批准写入"→ AI 才能写入

#### 5.2 R 类 vs C 类区别

| 维度 | R 类（专业知识规则） | C 类（历史案例） |
|---|---|---|
| 来源 | 法规 / 制度 / 标准 | 真实发生的项目教训 |
| 时效 | 长期稳定（除非法规修订） | 单次教训 |
| 验证 | 权威依据 | 事实结果 |
| 写入门槛 | 权威依据 + 适用边界 + 用户批准 | 真实发生 + 事实确认 + 用户批准 |
| 当前条目数 | 0（v3.0.0 启动时为空）） | 由外部真实历史案例库维护 |

#### 5.3 R 类与 A 类冲突解决

**当 R 类与当前项目招标文件（A 类）冲突时）**：
- **以 A 类为准**（当前项目规则优先级最高）
- AI 应在报告中明确标注"R 类与本项目招标要求不一致，已按本项目招标要求处理"

## 六、候选经验区协议

#### 6.1 候选经验定义

**AI 在审核中观察到但不构成规则的素材**：
- 模型一般知识 / 推断
- 单一项目观察（无法跨项目复用）
- 尚未验证的潜在风险

#### 6.2 候选区不是正式知识源

**禁止**：
- ❌ 正常投标审核不得以候选区作为判断依据
- ❌ 不得在报告中引用候选经验
- ❌ 不得把候选经验当作规则来要求用户

**允许**：
- ✅ AI 自动捕获候选经验（写入 `references/候选经验区.md`）
- ✅ 用户定期回顾候选区，决定是否升级为 R 类 / C 类

#### 6.3 候选经验格式

```
[YYYY-MM-DD][AI 推断][未升级]
- 风险描述：（一句话）
- 触发条件：（什么场景会触发）
- 关联项：（关联 A-N.x 或 R-XXX 或 C-XXX）
- 来源项目：（项目名称 + 日期）
- 待用户判断：升级 C 类 / 升级 R 类 / 不升级 / 已处理
```

## 七、报告末尾的"历史案例提醒"小节（v3.3.2 收口版）

> **v3.3.2 变更**：删除原"报告末尾的'历史案例对照'小节（v3.0.0 强化版）"硬性要求。
> 改为：**仅在 Report Gate 命中真实案例时**，在 8 模块正文**之后、附录之前**插入简短"历史案例提醒"小节。

**插入条件**：
- Report Gate 命中真实历史案例（C-XXX / P-XXX）
- 历史案例提醒的当前项目证据**必须**回到原文核实

**展示格式**（仅命中时）：

| 案例编号 | 提醒检查内容 | 当前项目直接证据 | 是否构成最终不符合 |
|---|---|---|---|
| C-002 | 项目经理姓名六处逐字比对 | "陈海岳" 六处一致 ✅ | ❌ 不构成（仅提醒） |

**禁止**：
- ❌ 把历史案例编号作为最终不符合判断的直接证据
- ❌ 在未命中案例时插入空表 / 占位符
- ❌ 改变现有 8 模块报告结构（必须保持模块 1-8 完整）
