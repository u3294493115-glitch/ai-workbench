## 三、文件分层解析（v2 细化）

### 3.1 主标书正文

投标方自制文件（技术标 / 商务标 / 资格审查资料册）。

**解析深度**：全量解析文字 + 嵌入图片（若有）。

**理由**：废标 / 资格 / 评分项分散在各处，必须通读。

### 3.2 关键资质类附件（强制逐张读取）

资质证书、营业执照、身份证、社保 / 纳税证明、信用中国截图、业绩合同、授权委托书等。

**解析深度**：嵌入图片 / 扫描件**必须逐张读取**。

**核对要点**：
- 资质证书：名称、等级、有效期、发证机关
- 身份证：姓名与投标文件中人员名单是否一致
- 社保证明：缴费月份是否覆盖招标文件要求的时间范围、缴费单位是否为投标人本单位
- 信用截图：截图来源网站、查询日期、查询结果（有无异常记录）
- 业绩合同：合同金额、签署日期、项目类型是否符合"类似项目"定义

### 3.3 大篇幅佐证材料（v2 明确策略）

财务报告、审计报告全文、检测报告全文、施工组织图集、技术规范等。

**解析深度**：仅做「存在性确认 + 关键页核对」，**不要求逐页通读**。

**v2 明确的"关键页"定义**：
- 封面（机构名称 / 报告期）
- 签字盖章页 / 审计意见页
- 核心结论页（资产负债表首页、主要财务数据页、检测结论页）
- **招标要求对应的章节**（如招标要求"2024 年度审计报告"，仅 OCR 该年度报告的封面+意见页+数据页）

**完整性声明中如实标注**：「已确认提供，OCR 关键页 X 页，未逐页复核」，并提示人工按需深读。

**理由**：此类材料篇幅大、信息密度低、通常不产生新的废标 / 资格条件，全量读是浪费且易冲淡关键项。

## 四、Docx 文件解析（v2 强化嵌入图片）

Docx 本质是 ZIP 包，文字和嵌入图片存储在不同位置：

| 内容 | 存储位置 | 提取方式 |
|---|---|---|
| 正文文字 | `word/document.xml` | 解析 XML，提取 `<w:t>` 节点 |
| **嵌入图片/证书扫描件** | **`word/media/`** | **v2 强制：导出全部二进制文件 + 逐张读取** |
| 图片与文字的对应关系 | `word/_rels/document.xml.rels` | 读取 Relationships，建立 rid 与 media 文件的映射 |
| 页眉页脚文字 | `word/header*.xml` / `word/footer*.xml` | 同正文解析方式 |
| 表格内容 | 同在 `document.xml` 的 `<w:tbl>` 节点 | 一并提取，不得遗漏 |

### 强制解析流程（v2）

```
步骤1：用 zipfile 打开 docx，调用 namelist() 探全貌
步骤2：确认 word/media/ 下是否有文件 → 有则全部导出到本地
步骤3：读取 document.xml.rels，建立 rid → 图片文件的映射表
步骤4：解析 document.xml，提取文字段落，同时记录每段落后紧跟的图片rid
步骤5：如 docx 含有 header/footer，同样解析
步骤6：向用户报告解析结果：
   - 文字段落：X 段
   - 嵌入图片：X 张（逐一列出文件名，便于用户核对）
   - 页眉页脚：有/无
步骤7：调用 Read 工具逐张读取图片，提取关键字段：
   - 资质证书：名称、等级、有效期、发证机关 → 入索引表
   - 业绩合同：合同金额、签署日期、项目类型 → 入索引表
   - 社保证明：缴费月份、缴费单位 → 入索引表
步骤8：只有当步骤1-7全部完成，才能进入"逐项核对"阶段
```

## 五、PDF 文件解析（v2.1.2 修订：高清优先 + 整页低缩放禁止下资格结论）

> **v2.1.1 重要修订**：废除"PDF 文字层有效 → 不调用 OCR/图片识别"的全局判断。
>
> **v2.1.2 进一步修订**：明确分工——
> - **文字层仅用于快速定位页码**（不做证据结论）
> - **关键资格证据优先进行高清页面视觉识别**（放大 / 裁切 / 高清渲染）
> - **OCR 仅在视觉识别困难时兜底**
> - **浏览器低缩放整页只能用于定位，禁止下资格结论**
>
> **核心原则**：**PDF 有文字层 ≠ 页面证据已经读取完整**。**整页低缩放看完 ≠ 关键字段已可核验**。
>
> 一个 100 页的扫描件 PDF，文字层可能只有目录 + 章节标题 + 部分合同条款可读，但所有证书扫描页（营业执照、资质证书、建造师证、B 证、社保、信用截图、业绩合同、竣工验收、管理体系认证）**仍然是图片**。如果按"文字层有效就不看图片"，这些关键证据会全部被判为"未提供证明材料"或"⚠️ 待人工复核"——这是真实任务中已被验证的系统性失败。

### 5.1 处理顺序（v2.1.2 强制）

```
[每个审查项 → 文字层快速定位页码]
       │
       ▼
[Step 1：用 pdftotext / pdfjs 提取该页文字层 → 仅用于定位页码]
       │
       ▼
[Step 2：判断该审查项所需关键字段是否已可从文字层取得]
       │
   ┌───┴───┐
   ▼       ▼
 [已取得] [未取得]
   │       │
   │       ▼
   │  [Step 3：高清页面视觉识别（放大 / 裁切 / 高清渲染）]
   │       │
   │       ▼
   │  [Step 4：视觉工具失败时 OCR 兜底]
   │       │
   │       ▼
   │  [Step 5：两者均失败 → ⚠️ 视觉识别失败（按状态规则 P-013）]
   │
   ▼
[原样提取 → 原样展示 → 逐字比较]
```

### 5.2 必须执行页面视觉识别的关键证据清单（v2.1.1 保留 + v2.1.2 强化）

以下证据类型，**无论整个 PDF 文字层是否有效，只要对应页面主要内容为图片、扫描件或文字层不能提取关键字段，就必须继续进行页面视觉识别**：

| # | 证据类型 | 必读关键字段 | 视觉识别要求 |
|---|---------|------------|------------|
| 1 | 营业执照 | 公司名称、统一社会信用代码、法定代表人、注册资本、成立日期、发证机关 | 高清视觉识别 |
| 2 | 企业资质证书（设计/施工/其他） | 证书编号、单位名称、资质等级、发证机关、发证日期、有效期 | 高清视觉识别 |
| 3 | 承装（修、试）电力设施许可证 | 许可证编号、单位名称、许可类别和等级、发证机关、有效期 | 高清视觉识别 |
| 4 | 安全生产许可证 | 证书编号、单位名称、发证机关、有效期 | 高清视觉识别 |
| 5 | 注册建造师证书 | 证书编号、姓名、级别、专业、注册单位、有效期 | 高清视觉识别（**必须逐字比对姓名**） |
| 6 | 安全生产考核 B 证 | 证书编号、姓名、类别、工作单位、有效期 | 高清视觉识别 |
| 7 | 社保证明 | 姓名、缴纳单位、参保险种、参保时间区间、证明截止时间 | 高清视觉识别（**关键字段遮挡不得自行补全**） |
| 8 | 信用查询截图 | 查询主体、查询内容、查询结果（有无记录）、截图来源网站 | 高清视觉识别 |
| 9 | 业绩合同 | 项目名称、项目类型、合同双方、合同金额、签约时间、工作范围 | 高清视觉识别（合同金额 / 签约日期 / 项目名称逐字提取） |
| 10 | 竣工验收证明 | 项目名称、验收时间、验收结论 | 高清视觉识别 |
| 11 | 管理体系认证证书（评分项） | 证书编号、认证类型、认证机构、有效期 | 高清视觉识别 |

### 5.3 严格禁止的判断逻辑（v2.1.1 + v2.1.2 强化）

> **❌ 禁止**："文字搜索不到 = 文件不存在"。
>
> **❌ 禁止**："整个 PDF 能提取文字 = 不再看图片"。
>
> **❌ 禁止**：因为一个字段识别失败，就把整个资格项笼统判为"待确认"。
>
> **❌ 禁止（v2.1.2 新增）**：在浏览器低缩放整页状态下"看个大概"就下资格结论。
>
> **❌ 禁止（v2.1.2 新增）**：用整页低缩放截图作为"已视觉识别"证据。

### 5.4 视觉识别质量分级（v2.1.2 新增，强制使用）

| 级别 | 适用场景 | 工具 | 是否可用于资格结论 |
|---|---|---|---|
| **L1 高清视觉识别** | 关键资格证据（11 类清单） | 多模态视觉工具 + 放大 / 裁切 / 高清渲染 | ✅ 可下资格结论 |
| **L2 整页中缩放** | 用于概览、定位、辅助阅读 | 浏览器或 PDF 阅读器中缩放（50%-100%） | ❌ 仅供定位，不下结论 |
| **L3 整页低缩放** | 用于快速浏览、目录核对 | 浏览器或 PDF 阅读器低缩放（<50%） | ❌ 仅供定位，禁止下结论 |
| **L4 OCR 兜底** | L1 / L2 / L3 均失败 | OCR 工具链 | ⚠️ 仅作辅助，置信度低 |

**强制规则**：
- 涉及资格结论的小字字段（企业名称 / 人员姓名 / 证书编号 / 证书等级 / 有效期 / 注册单位 / 社保单位），**必须达到 L1 高清视觉识别**
- **禁止**用 L2 / L3 整页状态下的"看个大概"作为资格结论依据
- 必须通过放大、裁切或高清页面渲染后确认

### 5.5 状态分类（v2.1.2 强化，强制使用）

每个关键证据页面，AI 必须明确区分以下四种状态之一：

| 状态 | 含义 | 后续动作 |
|------|------|---------|
| **✅ 满足** | **清晰且一致**：L1 高清视觉识别或文字层已确认关键字段全部满足招标要求 | 标记通过，列出已读取的关键字段值（带引号原样） |
| **❌ 不满足** | **清晰且明确不一致**：L1 高清视觉识别确认关键字段存在但与招标要求不符 | 明确指出哪个字段不符（带引号原样差异） |
| **⚠️ 视觉识别失败** | **已提供但图片确实无法识别关键字段**：L1 / L4 均失败 | 明确写出"已发现[文件类型]页面，但[具体字段]视觉识别失败，需人工查看原页 PXX" |
| **❌ 缺失** | **未提供证明材料**：该页面在投标文件中不存在 / 找不到对应页 | 列为资格硬条件缺失，按最高风险处理 |

> **不允许出现**：
> - "通过（前提：确认 X）"、"待 OCR"、"待人工复核"——除非已经走完 5.1 的 Step 5 流程
> - 把"明确不一致"写成"待确认"——必须按本表区分 ✅ / ❌ / ⚠️ / ❌缺失

### 5.6 OCR 工具链（v2.1.1 保留 + v2.1.2 强化）

Skill 自带的 scripts/ 目录提供最小化 PDF 嵌入图像提取脚本：

- `scripts/extract_pdf_images.mjs` — 提取 PDF 内嵌入的图像资源（paintImageXObject），导出为 PNG
- 调用方式：`node scripts/extract_pdf_images.mjs <pdf路径> <输出目录>`

提取出的 PNG 文件，应复制到 `<OS_TEMP_DIR>\`（Claude Code 多模态工具默认可访问路径），再通过 `mcp__<VISION_TOOL>__understand_image` 或其他多模态工具识别。

**v2.1.2 强化**：
- 提取的 PNG 默认按 L1 高清视觉识别处理（不缩放、不压缩）
- 多模态工具识别时必须**逐字段原样提取**，带引号记录
- OCR 仅在 L1 视觉识别困难时调用（兜底），输出置信度

### 5.8 定向视觉核验流程（v3.0.0 新增，强制规则）

> **核心问题**（来自该项目（招标方X / 投标人E））：v2.1.2 流程中，AI 仅做"文字层定位 → 渲染候选页 → 视觉识别"，但缺少"以招标要求为起点 → 列出必须证据集 → 跨页验证"的闭环。结果就是 P22 只看了封面就判"证书类型不符"——而 P22 后续的页面可能就是证书主体。
>
> **v3.0.0 新增**：每个资格硬条件的核验必须遵循以下闭环。

#### 5.8.1 定向视觉核验流程（强制）

> **v3.1.0-rc 备注**：候选页可由 `scripts/pdf_page_recon.mjs` 输出 `<pdf>.recon.json` 提供，
> 也可由人工选题。定向视觉核验规则保持不变。详见
> `references/页面侦察与视觉候选筛选策略.md` 第三节。

```
[1] 列出本条件要求的"必须证据集"
   例 1：注册建造师执业证书
     → 证书主体页（必须包含"注册"二字）
     → 持证人姓名 / 专业 / 证书编号 / 聘用企业 / 注册有效期
   例 2：6 个月任意 1 个月社保证明
     → 社保章 + 缴纳单位 + 参保月份 + 姓名
   例 3：信用截图加盖公章
     → 截图（信用中国 / 国家企业信用信息公示系统）
     → 公章（联合体/投标方）
   例 4：业绩证明
     → 合同关键页（项目名称 / 金额 / 签约日期）
     → 竣工验收文件

[2] 用文字层 / 目录定位候选页
   - 仅定位，不下结论
   - 记录候选页范围（如 P22-P24）

[3] 对候选页进行 L1 高清渲染
   - canvas 渲染 PNG @ 2.5x
   - 不缩放、不压缩

[4] 视觉读取关键字段
   - 多模态工具识别
   - 逐字段原样提取，带引号记录

[5] 检查连续后续页（E-006 页面连续性强制要求）
   - 例：证书跨 P22-P23 → 必须检查 P23 / P24，不能仅看 P22
   - 例：社保可能跨 P24-P26 → 必须检查 P25 / P26

[6] 判定结论必须记录五态之一
   - ✅ 已核验满足
   - 🔵 初步满足（部分子项待确认）
   - 🔎 AI 尚未完成检索（AI 立即继续）
   - ⚠️ 已找到但关键字段无法视觉识别
   - ❌ 已完成针对性搜索仍未找到
   - ❌ 明确不满足
```

#### 5.8.2 禁止行为

- ❌ **禁止**"文字搜索不到 = 文件不存在"
- ❌ **禁止**"PDF 有文字层 = 不再看图片"
- ❌ **禁止**因一个字段识别失败就把整个资格项笼统判为"待确认"
- ❌ **禁止**在浏览器低缩放整页状态下"看个大概"就下资格结论
- ❌ **禁止**只看证书封面 / 第一页后就下"证书类型不符"结论（**E-006 页面连续性**）
- ❌ **禁止**整页低缩放截图作为"已视觉识别"证据
- ❌ **禁止**把"AI 尚未完成的检索"甩给人工（v3.0.0 五态规则）

#### 5.8.3 最小充分证据集原则

**v3.0.0 新增**：对于几十页、上百页财务报告 / 审计报告 / 大篇幅合同，仅核验**当前招标条件所需的最小充分证据集**：

```
- 招标要求"2024 年度审计报告" → 仅 OCR 封面 + 意见页 + 关键数据页
- 招标要求"业绩合同关键页" → 仅 OCR 合同首页（合同双方 / 金额 / 签订日期）
- 招标要求"竣工验收文件" → 仅 OCR 验收首页 / 签字页
```

**禁止**全文逐页阅读大篇幅佐证材料。

#### 5.8.4 E-006 页面连续性回归测试用例

> 证书跨连续数页 → 不能只看封面后立即下结论，应检查其后连续页面。

```
示例：P22 显示"一级建造师职业资格证书"封面
- 错误：仅看 P22 → 判 "证书名不含'注册' → ❌ 不满足"
- 正确：检查 P22-P25 → 若 P23 / P24 是注册证书主体（带"注册"二字 + 注册编号）
       → 结论：✅ 已核验满足（同时区分职业资格 vs 注册执业证两层）
```

## 九、与 winocr-table-extract 的配合

`winocr-table-extract` skill 提供了 Windows 系统自带 OCR + Python 脚本的方案。

**v2 借鉴**：
- 大批量截图 OCR 用 winocr-table-extract 的脚本批量处理
- 不下载 Tesseract 中文包（避免 CDN 失败）
- 输出 JSON 结构化数据

**v2 不借用**：
- winocr-table-extract 主要是表格数据抽取，标书审核需要更细粒度的字段抽取
- 不应替换主 OCR 流程
