# 专业知识规则库（v3.0.0 收口）

> **v3.0.0 收口说明**：
>
> 本文件是 R 类（专业知识规则）的唯一存储位置。
>
> **R-Candidate 不属于正式规则，不得用于投标硬判断**——仅作 AI 主动查询官方资料的起点。
>
> **写入门槛**（法规 / 制度型规则）：
> 1. **权威依据明确**——能引用具体文件 / 标准号 / 主管部门答复
> 2. **适用边界明确**——能说清"适用于 X，不适用于 Y"
> 3. **用户明确批准**——AI 输出建议 → 用户回复"批准写入"→ AI 才能写入
>
> **只有无明确法规依据的经验型规律**，才考虑多项目验证。
>
> **当前状态**：本文件**无任何正式 R 规则**。所有条目均为 R-Candidate（未授权，不构成规则）。

---

## 一、R 类规则定义

**可跨项目复用** + **有官方权威依据**（住建部 / 人社部 / 发改委 / 国家级标准 / 主管部门答复）的专业判断。

R 类与 C 类（历史案例）区别：

| 维度 | R 类（专业知识规则） | C 类（历史案例） |
|---|---|---|
| 来源 | 法规 / 制度 / 标准 | 真实发生的项目教训 |
| 时效 | 长期稳定（除非法规修订） | 单次教训 |
| 验证 | 权威依据 | 事实结果 |
| 写入门槛 | 权威依据 + 适用边界 + 用户批准 | 真实发生 + 事实确认 + 用户批准 |

---

## 二、规则格式

每条规则必须包含：

| 字段 | 说明 |
|---|---|
| 规则编号 | R-XXX |
| 规则标题 | 一句话描述 |
| 规则内容 | 详细说明 |
| 权威依据 | 具体文件 / 标准号 / 主管部门答复 |
| 来源 | 引用文件标题 + URL 或文号 |
| 适用条件 | 什么场景下使用 |
| 不适用条件 / 例外 | 什么场景下不使用 |
| 最后核验日期 | YYYY-MM-DD |
| 写入日期 | YYYY-MM-DD（用户批准日） |
| 写入授权 | 用户名 + 授权时间 |
