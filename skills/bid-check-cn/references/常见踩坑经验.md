## 三、应对动作清单（v2 保留）

每条踩坑经验，AI 在报告中给出具体应对动作。

### 坑 #1 投标保证金到账延迟
**AI 检查动作**：
- 提取招标文件中的保证金要求（金额、截止时间、收款账户、缴纳主体、备注）
- 检查投标资料中是否有保证金申请、付款安排、回单、平台确认
- 输出"保证金闭环核查清单"

**应对动作**：
- 提前 3 个工作日打款
- 打款后立即通知财务确认到账
- 平台确认识别状态

### 坑 #9 单位名称一字之差
**AI 检查动作**：
- 提取招标文件标准主体名称
- 提取投标文件、申请书、保证金资料中的所有单位名称
- **逐字比对**（P-013 强制）：少字、多字、简称、括号、分公司、全角半角

**应对动作**：
- 投标方自查所有单位名称一致性
- 由商务/财务确认保证金识别无误

### 坑 #10 资质与人员证明链断裂
**AI 检查动作**：
- 建立"招标要求—投标响应—证明材料"映射表
- 重点检查 16 项（证书 + 社保 + 业绩 + 验收报告）——本检查与外部案例库 C-XXX / P-XXX 无关；外部历史案例库的统一读取点为 [Report Gate]，不得在此提前引用

**应对动作**：
- 投标方补充缺失附件
- 由标书负责人逐项核验证书有效期、人员一致性、签章完整性

### 坑 #11 配合厂家材料缺失
**AI 检查动作**：
- 建立《配合厂家材料检查清单》
- 核对标书目录中"否"项是否真有依据（招标文件某条不适用），而非"懒得提交"
- 信用查询截图须含查询日期

**应对动作**：
- 由配合厂家提供全部要求材料
- 配合厂家材料须加盖配合厂家公章

### 坑 #12 模板占位符未替换
**AI 检查动作**：
- 全文搜索"（投标人名称）""（法定代表人）""（日期）""（电话）""（地址）"
- 检查空白字段（签名、日期、职称、电话）
- 核对社保有效期

**应对动作**：
- 全文替换占位符
- 逐页填写必填字段
- 更新社保证明至最新月份

### 5.1 通用经验（沉淀为 P-013 / P-014 / P-015）

#### 通用经验 #1｜施工总承包资质存在 ≠ 承装许可证 + 安许证也存在
**错误做法**：投标人提供了电力工程施工总承包资质证书，AI 自动判定"施工总承包 + 承装许可证 + 安许证"三项组合要求通过。

**正确做法**：三项资质是**独立硬条件**，必须**逐项分别核验**：
- A：电力工程施工总承包三级/以上 或 机电工程施工总承包三级/以上
- B：《承装（修、试）电力设施许可证》承装类三级/以上
- C：安全生产许可证

任一项缺失或无效 = 资格审查不通过。

**沉淀为规则**：P-014 组合连词必拆为 AND/OR/AND+OR 表达式（"X 或 Y，并具备 Z 及 W" → (X OR Y) AND Z AND W）

#### 通用经验 #2｜项目经理姓名必须逐字比对
**错误做法**：AI 用模糊匹配认为"陈国瑞"≈"陈国瑞相近"。

**正确做法**：姓名必须**逐字比对**，错一个字 = 不一致 = 资格重大风险。

**触发位置（六处必查）**：
- 投标文件资格声明中的项目经理姓名
- 投标文件项目经理资质页的姓名
- 投标文件授权委托书中的被授权人姓名
- 投标文件拟派本项目负责人及主要人员情况表的姓名
- 投标文件社保证明的姓名
- 投标文件 B 证 / 注册建造师证书的姓名

**沉淀为规则**：P-013 关键字段原样提取后逐字比较

#### 通用经验 #3｜职业资格证书 ≠ 注册建造师执业证书
**错误做法**：投标文件提供"一级建造师职业资格证"（通过考试，未注册），AI 看到"一级建造师"就判满足"二级及以上注册建造师执业证书"。

**正确做法**：招标要求的是"**注册**建造师执业证书"（已注册到具体企业、有注册编号、有有效期），不是"职业资格证"。

**判定要点**：
- 证书名称必须包含"注册"二字
- 必须有"注册编号"（如"粤2442024202407479"）
- 必须有"聘用企业"信息
- 必须有"专业注册有效期"

**沉淀为规则**：P-013 关键字段原样提取后逐字比较（证书名称 / 编号 / 聘用企业 / 有效期）

#### 通用经验 #4｜社保证明关键字段被遮挡不得自行补全
**错误做法**：社保扫描件中"缴纳单位"、"参保月份"等关键字段被公章、文字遮挡，AI 仍标"满足"。

**正确做法**：社保证明的核心字段（姓名、单位、参保月份）必须**可清晰辨认**。如果被遮挡导致无法证明：
- 人员是否在投标人单位工作
- 社保是否在招标要求的时间窗口内
- 是否为本单位正式人员

应作为 ❓ 无法确认（情形 B：⚠️ 视觉识别失败） 或 ❌ 不满足（按遮挡程度），**不能笼统判为"待人工复核"**。

**沉淀为规则**：P-013 关键字段原样提取后逐字比较（社保证明的姓名 / 单位 / 月份）

#### 通用经验 #5｜PDF 有文字层 ≠ 证书图片已读取
**错误做法**：投标文件 PDF 是扫描件，但 pdftotext 仍能提取出文字（目录、章节标题、合同条款等），AI 根据"文字层有效→不调用 OCR"规则**跳过所有证书扫描页**。

**正确做法**：**PDF 有文字层 ≠ 页面证据已经读取完整**。判定流程必须是页面级的：
1. PDF 文字层提取
2. 判断该审查项所需关键字段是否已经取得
3. 未取得 → 高清页面视觉识别（放大 / 裁切 / 高清渲染）
4. 视觉识别困难时 OCR 兜底
5. 两者均失败 → 才允许标 ❓ 无法确认（情形 B：⚠️ 视觉识别失败）

**沉淀为规则**：OCR 策略 v2.1.2 第五节（页面级证据判断 + 高清优先 + OCR 兜底）

#### 通用经验 #6｜主条款+注释+例外+替代核验路径必须一并提取
**错误做法**：招标要求"项目经理具有注册建造师执业证书"，投标文件提供电子证书但缺手写签名，AI 直接判 ❌ 不满足。

**正确做法**：必须检查主条款后是否存在**注释、例外、替代核验路径**。例如：
> "若招标文件规定电子证书超过使用有效期、缺手写签名等情况可通过官方平台核验，必须把该替代核验路径一并提取。"

**AI 强制动作**：
- 提取主条款时，同步扫描"注、说明、例外、若……则……、可通过……核验"
- 注释/例外/替代核验路径必须与主条款一并进入审查表
- AI 不得只提取主条款后直接判不合格
- 最终结论只服从**当前项目招标文件**

**沉淀为规则**：P-015 主条款+注释+例外+替代核验路径一并提取

### 5.2 项目特定教训（仅适用本次项目上下文，不得上升为通用规则）

#### 项目特定教训 #1｜电子建造师证缺手写签名 = 资格不通过？

**风险描述**：在某九州项目审核中，电子建造师证缺手写签名，AI 最初判 ❌ 不满足。

**错误解读**：直接把"电子证书缺手写签名 = 资格不通过"上升为通用规则。

**正确处理**：
- 这是**项目特定教训**：该项目的招标文件可能规定"电子证书可通过官方平台核验"
- 通用经验应该是："遇到证书签名、有效期等问题时，**必须检查本项目招标文件是否存在例外或官方平台替代核验规则**，最终结论只服从当前招标文件"（即通用经验 #6）
- **不能**把"电子建造师证缺手写签名 = 资格不通过"写成通用规则
- 必须查本项目招标文件的例外或替代核验规则后再下结论

#### 其他项目特定教训（按需补充）

> AI 在 Stage 5 经验回流时，应明确区分"通用经验"vs"项目特定教训"。项目特定教训仅供本次项目决策参考，**不得写入 references/常见踩坑经验.md**。

#### 通用经验 #7｜本模型 视觉 1026 内容策略拒绝（已确认 2026-09-04）
**错误做法**：调用 视觉 API 识别建造师证书、身份证、营业执照等含个人信息的页面，被错误码 内容策略错误码 拒绝后，AI 跳过该页，用同章节其他页代替证据。

**正确做法**：
- 1026 错误 = 本模型 视觉服务的内容策略拒绝，不是图片质量或网络问题；
- 第一时间重试 1 次，使用脱敏 prompt：移除"姓名：XXX"、"身份证：XXX"、"证书编号：XXX" 等具名提示词，改为"识别此页证书类型、颁发机构、有效期，不要复述个人身份信息"；
- 重试仍失败 → 标记该页 `vision_blocked`，**不得**用相邻页代替整组证据；
- 把失败页和重试记录写入 `_work/vision_calls.json`。

**沉淀为规则**：SKILL.md v3.3.1 "视觉失败分级" 章节 + `scripts/py/evidence_manifest.mjs` 状态聚合。

#### 通用经验 #8｜手写年份 / 数字 误识别（已确认 2026-09-04）
**错误做法**：扫描件 / 验收单上手写"2025-12-09"被视觉模型识别为"2023-12-09"，AI 直接采纳为确定性事实，与合同日期矛盾后升级为重大风险。

**正确做法**：
- 手写字段默认低置信度（`low_confidence`）；
- 关键字段（日期、金额、签字）发生高风险矛盾时，必须二次复核：放大 2.5x 重渲染 + 独立第二次识别；
- 两次结果不一致 → 标记 `unconfirmed`，报告附"AI 无法判断，请人工核对原件"，**不得**直接作为废标 / 资格否决依据。

**沉淀为规则**：SKILL.md v3.3.1 "字段置信度" 章节 + `evidence_manifest.low_confidence_pages` 字段。

## 六、v2.1.2 新增通用预防规则 P-013 / P-014 / P-015

### P-013｜关键字段原样提取后逐字比较

**适用场景**：所有资格关键字段。

**强制规则**：
- 必须按以下顺序执行：原样提取 → 原样展示 → 逐字比较
- **禁止** AI 自行：简称化、纠错、补全、推测、归一化
- **禁止** 把"明确不一致"写成"待确认"

**12 项强制字段清单**：
1. 投标人单位名称（含分公司、子公司、联合体成员）
2. 项目经理姓名 / 身份证号
3. 技术负责人 / 安全员姓名
4. 资质证书编号 / 等级 / 发证机关 / 有效期
5. 注册建造师证书编号 / 注册编号 / 有效期
6. 安全生产许可证编号 / 有效期
7. 承装（修、试）电力设施许可证编号 / 等级 / 有效期
8. 业绩合同项目名称 / 合同金额 / 签约日期
9. 社保证明姓名 / 缴纳单位 / 参保月份
10. 信用查询截图查询日期 / 查询主体
11. 管理体系认证证书编号 / 有效期
12. 投标保证金金额 / 缴纳日期 / 收款账户

**AI 自检动作**：
1. 提取原文关键字段值（带引号原样）
2. 与投标响应字段逐字比对
3. 不一致 → 直接标 ❌ 不满足（不允许 AI 自定"应该一致"）
4. 缺失字段 → 直接标 ❌ 缺失（不允许 AI 自定"应该存在"）

### P-014｜组合连词必拆为 AND/OR/AND+OR 表达式

**适用场景**：清单 A 中任何一条要求。

**强制规则**：
- 必须按**逻辑表达式**拆分（不是机械拆行），保留原文逻辑关系
- 必须支持：AND / OR / AND+OR 组合 / 条件触发 / 注释 / 例外条件 / 替代证明路径

**拆分原则**：
- 每条要求必须能表达为一个或多个布尔表达式
- 每行 / 每个表达式必须能独立判定 ✅/❓/❌
- 每个表达式必须对应至少一个证明材料

**示例**：
- 招标原文："电力工程施工总承包三级以上或机电工程施工总承包三级以上，并具备承装类三级以上及安全生产许可证"
- 必须表示为：**（电力总包 ≥ 三级 OR 机电总包 ≥ 三级）AND 承装 ≥ 三级 AND 安全生产许可证**
- AI 不得简化为三行独立项
- AI 不得简化为一行 AND 全部

**禁止**：
- 简单规定"每遇到且/并/或就拆一行"
- 拆分后丢失 OR / 条件触发 / 例外 逻辑

**AI 自检动作**：
1. 扫描清单 A 每条原文
2. 提取逻辑表达式（AND / OR / 条件触发 / 注释 / 例外 / 替代核验）
3. 表达式与原文逻辑关系不一致 → AI 自检不通过

### P-015｜主条款+注释+例外+替代核验路径一并提取

**适用场景**：清单 A 任何主条款后存在注释、说明、例外、替代核验路径。

**强制规则**：
- 主条款后出现"注、说明、例外、若……则……、可通过……核验" → 必须与主条款一并进入审查表
- AI 不得只提取主条款后直接判不合格
- 最终结论必须先检查本项目招标文件的例外 / 替代核验规则

**示例**：
- 招标原文："项目经理具有注册建造师执业证书。注：电子证书超过使用有效期、缺手写签名等情况可通过官方平台核验。"
- 审查表必须记录：
  - 主条款：项目经理具有注册建造师执业证书
  - 例外：电子证书超过使用有效期、缺手写签名可通过官方平台核验
  - AI 审核动作：检查电子证书 → 若缺签名但官方平台可核验 → 应给出 ✅ 满足 + 注明核验依据，而非直接 ❌ 不满足

**禁止**：
- 只提取主条款，忽略注释 / 例外 / 替代核验路径
- 把"项目特定教训"上升为通用规则（如"电子证书缺手写签名 = 资格不通过"）

**AI 自检动作**：
1. 扫描清单 A 每条主条款
2. 检测后文是否有"注 / 说明 / 例外 / 若……则…… / 可通过……核验"
3. 命中但未一并提取 → AI 自检不通过
