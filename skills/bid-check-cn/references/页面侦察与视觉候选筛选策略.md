## 二、能力 A：所有页面都进入廉价侦察

### 2.1 脚本

`scripts/pdf_page_recon.mjs <pdf_path> [out_dir]`

### 2.2 每页输出

```json
{
  "page": 1,
  "w_pt": 595, "h_pt": 842,
  "page_area_pt2": 501141,
  "text_chars": 850,
  "has_text": true,
  "image_count": 2,
  "largest_image_area_pt2": 1486934,
  "largest_image_area_frac": 2.97,
  "render_bytes_estimate": 1503423,
  "is_visual_candidate": false,
  "candidate_reasons": ["text_only"],
  "cross_page_propagated_for": null
}
```

### 2.3 与文本层的关系

| 任务 | 工具 | 用途 |
|---|---|---|
| **侦察每页元数据** | `pdf_page_recon.mjs` | 文本长度 / 图片数量 / 图片面积 / 大图占比 |
| **文本层全文 grep** | `pdftotext` / pdfjs `getTextContent` | 仅用于定位关键词候选页（不替代视觉识别） |

重要：**PDF 有文字层 ≠ 页面证据已经读取完整**（与 `文件解析与视觉核验策略.md` 5.3 一致）。侦察只能判定页面"是否值得看图"，不能判定"图中字段是什么"。

## 三、能力 B：候选页才进入渲染

### 3.1 4 类 Case 判定

| Case | 特征 | 判定 | 渲染？ |
|---|---|---|---|
| A 文字页 | `text_chars ≥ 30` 且 `最大图占比 < 20%` | `is_visual_candidate = false` | 否 |
| B 纯扫描证书页 | `text_chars < 30` 且 `image_count ≥ 1` | `true`，reason `scanned_cert_page` | 是 |
| C 文字 + 大面积证书图 | `text_chars ≥ 30` 且 `最大图占比 ≥ 20%` | `true`，reason `text_plus_major_image` | 是 |
| D 普通 Logo / 小图标 | `text_chars ≥ 30` 且 `最大图占比 < 5%` | `false`，reason `text_with_small_icons` | 否 |

补充：
- **完全空白页** (`text=0` 且 `images=0`) → `false`，reason `blank_page`
- **定向视觉核验失败页** → `true`，reason `recon_failed_treated_as_candidate`（保守）

### 3.2 阈值

| 阈值 | 默认值 | 含义 |
|---|---|---|
| `TEXT_THRESHOLD` | 30 | < 30 字符视为"几乎无 native text" |
| `MAJOR_IMAGE_FRAC` | 0.20 | 最大嵌入图占页面面积 ≥ 20% 视为"大面积" |
| `LOGO_FRAC` | 0.05 | < 5% 视为"小 logo / 图标" |

### 3.3 跨页传播（任务书第九节 + E-006）

> **核心问题**：P116 / P117 是同一张注册证书跨页（P22-P25 历史教训）。如果只看 P116 封面就下结论，会漏掉主体页。

**机制**：

- 候选页 N → 检查 N+1 是否本身已为候选
- 若是 N+1 **不是**候选 **且** N+1 的 `image_count ≥ 2`：把 N+1 标记为 `cross_page_propagated_from_<N>`
- 单向 (N → N+1)，不级联（N+1 不会触发 N+2）

**不传播条件**：
- N+1 已有 `text_chars ≥ 30` 且 `image_count = 1`（典型"文字页 + 页眉 logo"）→ 不传播 → 不渲染
- N+1 已是候选 → 不重复标记

### 3.4 范围合并

`scripts/build_visual_manifest.mjs` 接收 `<pdf>.recon.json` 后，把连续候选页合并为 `[start, end]` 区间，调用 `render_pdf_pages.mjs` 单次渲染整段（减少 pdftoppm 调用次数）。

## 四、能力 C：资料复用辅助候选（仅 Stage 0 阶段）

### 4.1 资质库只读

`scripts/read_qualification_library.mjs` 解析 `合作单位资质库 v2` 的 Markdown，输出内存索引。**绝不**自动修改库文件；**绝不**写入 `output/_work/qualification_index.json`。

### 4.2 Tier 映射（D4）

| tier | 复核状态枚举样例 | 用途 |
|---|---|---|
| `HIGH` | 已人工复核通过 / 已确认（用户复核通过） | 可作为**高可信事实**来源 |
| `MEDIUM` | 已提取 / 已识别 / 已提供 | 仅作**辅助候选证据** |
| `LOW` | 待人工复核 / 待OCR / 待OCR/待确认 | **人工确认**参考 |
| `NOT_FOUND` | 未发现 / blank / 主体关系待确认 / 全称未发现 | "库里没数据"，不代表"主体不存在" |

### 4.3 三条硬约束（任务书第十一节 + 4.1-4.3）

1. **资质库有 ≠ 本次投标文件已提交** — 即使库里 HIGH tier 已有"某新能源公司营业执照"，投标 PDF 没有该材料也必须判 `❌ 完成针对性搜索仍未找到`。
2. **只复用事实字段** — 公司名、统一社会信用代码、证书编号、有效期、单位等**字段值**。不复用 `本项目符合` / `本项目通过` 等**项目结论**。
3. **不同 tier 不等同** — 已人工复核（HIGH）资料可作高可信事实；OCR 待复核（LOW）资料**只能作辅助候选**，不能直接支撑 PASS。

### 4.4 已被否决的路线

- ❌ 精确 SHA256 hash 复用 — 任务书第五节实验已确认在真实样本中命中率 = 0/4 方法（见 `scripts/hash_match_experiment.mjs` 实验结论 `ZERO_HASH_MATCHES`）
- ❌ 模糊匹配 / 向量数据库 / perceptual hash / embedding — 任务书第六条禁止

## 六、与 Step 0 强制门控的关系

`SKILL.md` Step 0 要求"用文件路径反查解析产物是否存在 + 关键字扫描验证关键章节是否被读到 + 列出每张图片/扫描件解析状态"。

**v3.1.0 起，推荐在 Step 0 增加可选步骤**：

```
[可选] 调用 pdf_page_recon.mjs：
   - 产出 <pdf>.recon.json
   - 在 Step 0 自检报告里写出 total_pages / 候选页数 / 跨页传播数
   - 不强制；不替代既有文本层解析
```

**禁止**：
- v3.1.0 不强制要求重跑侦察；v3.0.2 旧流程完全保留
- 旧 SKILL.md / references / evals 文件不动
