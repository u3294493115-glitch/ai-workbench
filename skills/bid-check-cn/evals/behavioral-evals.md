# 行为级 Eval 套件（v3.0.0 收口）

> **v3.0.0 收口说明**：本文件是真正的行为级 Eval（区别于 `static-rule-check.md` 的文档存在性检查）。
>
> **每个 Eval 必须包含**：
> 1. 输入（招标要求 + 投标材料描述）
> 2. 必要上下文
> 3. 期望行为
> 4. 禁止行为
> 5. Agent 实际输出（运行时填入）
> 6. PASS / FAIL
> 7. 失败原因（如有）

---

## 运行方式

> ⚠️ **重要**：行为级 Eval 必须**真正调用当前 bid-check-cn Skill 让模型做判断**，不是 grep SKILL.md。

### 手动运行流程

```
[1] 准备本文件中的某个 E-XXX 用例（输入 + 期望 + 禁止）
[2] 启动 Claude Code，加载 bid-check-cn Skill
[3] 提供该 E-XXX 的输入作为新投标项目
[4] 观察 Agent 实际输出
[5] 对照"期望行为"vs"禁止行为"判定 PASS / FAIL
[6] 失败 → 定位 Skill 哪条规则未落实 → 修复 → 重跑
```

### 自动化运行（未来）

如未来有 Claude Code 自动化测试框架，可按上述手动流程自动化：
- 输入场景 → 加载 Skill → Agent 输出 → 对照 PASS / FAIL

### 期望行为

2. B 证核验点 ✅ 已核验满足（含页码 + 字段）
3. 社保核验点 ❓ 无法确认，且 ❓ 行含三要素：
   - **原因**：文字层 grep "社保" = 0 命中；P68-P75 扫描页未视觉核验
   - **已核验**：grep "社保" / "社会保险" / "参保" 三个同义词均 0 命中；P52 视觉确认 B 证有效但无社保字段

4. 不得用 ⚠️ "已找到但关键字段无法视觉识别"（因为 AI 还没找过）

### 禁止行为

- ❌ 文字层 grep 0 命中 → 直接判 ❌缺失（必须先完成视觉核验）
